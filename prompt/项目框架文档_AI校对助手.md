# 出版校对AI助手 · 项目框架文档

> 版本:v1.0 · 用途:指导后续使用 Claude Code 分阶段开发 · 使用者:单人本地使用

---

## 1. 项目定位

一个辅助出版编辑校对工作的本地 AI 工具,替代现有"手动拖文档进大模型网页版 + 手动整理 Excel"的人工流程。

核心定位三句话:

- **对话式校对工作台**,而非"上传即走"的单向表单工具。校对结果可逐条追问、标记采纳/拒绝,最终导出 Excel 归档。
- **分层输出结果**:校对结论不是非黑即白的错误列表,而是按"确定性错误 / 存疑待核实 / 引文类 / 风格可选"四层呈现,把 AI 不可靠的部分显式交还人工判断。
- **单人本地运行**:无账号权限系统,暂不部署服务器,数据全部落在本地(SQLite + 本地文件夹)。

---

## 2. 要解决的实际问题(需求背景)

出版编辑在"人工 + AI 网页版辅助"的现有校对流程中,存在以下痛点:

### 2.1 人工侧痛点

| 编号 | 痛点 | 说明 |
|---|---|---|
| P1 | 基础语言问题量大易漏 | 错别字、标点误用、词语搭配不当往往同时大量出现,人工逐条核查容易遗漏 |
| P2 | 逻辑类问题依赖上下文 | 语序混乱、指代不明等表述逻辑问题,需要编辑结合上下文判断,不是简单对错题 |
| P3 | 三审三校采纳负担重 | 面对 AI 标出的大量修改点,人工逐条判断采纳与否负担大,容易遗漏或误判 |

### 2.2 AI 侧三类系统性误判(必须交由人工判断,不能直接采纳)

| 类型 | 表现 | 系统必须做的事 |
|---|---|---|
| **引文类** | AI 按现代语感修改引文用字,但引文必须忠实原文 | 只标注提示,**默认不建议改动**,不得自动判定为错误、不得直接给出修改建议 |
| **事实知识类** | AI 误改人名、职务、历史事实等知识性内容(把对的改错) | 不能默认可信,必须标注**"存疑,建议人工核实"**,而非给出"应改为"的确定性结论 |
| **风格可选类** | AI 修改改与不改都不影响正确性的表达 | 标注优先级为**"可选"**,单独归类,不与真正错误混在一起 |

### 2.3 由此确定的两条设计铁律

1. **结果必须分层输出**:确定性错误 / 存疑待核实 / 引文类 / 风格可选,四层贯穿展示、追问、标记、导出全链路。
2. **交互必须是对话式**:用户能针对具体某一条建议追问("为什么建议这么改""这是不是误判"),并逐条标记接受/拒绝(拒绝可记录理由),而不是只能整体下载一份 Excel 了事。

## 3. 功能范围(第一版)

两个功能是**独立的两条工作流**,交互模式一致(均为对话式)。

### 功能一:标准校对

| 项目 | 内容 |
|---|---|
| 输入 | 单份 PDF / Word |
| 处理 | 按校对提示词(十类检查维度 + 两条补充规则)校对,结果按四层分类 |
| 交互 | 对话式逐条/分组展示问题;每条标注所属分层;可追问;可标记采纳/拒绝(拒绝可记录理由) |
| 输出 | Excel 校对清单(格式见第 8 章) |

### 功能二:原稿比对

| 项目 | 内容 |
|---|---|
| 输入 | 原稿 Word + 排版稿 PDF/Word |
| 处理 | 逐段比对差异,区分"排版调整(不算错误)"与"实质性内容改动(需确认)" |
| 交互 | 对话式展示差异;可追问;可标记状态 |
| 输出 | Excel 差异清单 |

## 5. 核心工作流

### 5.1 工作流一:标准校对

```
上传文档 → 解析 → 分块 → 逐块LLM校对 → 结果分层 → 对话式展示
                                                    │
                              ┌──────────────────────┤
                              ▼                      ▼
                          用户追问 ◀──────────▶ 用户标记采纳/拒绝
                              │                      │
                              └──────────┬───────────┘
                                         ▼
                                     导出Excel
```

分步说明:

1. **上传与解析**:用户上传单份 PDF/Word;解析文本,PDF 需识别双栏排版并还原正确阅读顺序,记录页码/位置信息。
2. **分块**:长文档(最多 100+ 页)按块切割,块间保留上下文重叠,避免跨块问题漏检。
3. **逐块校对**:每块携带校对提示词(含引文保护、事实置信度两条补充规则)调用 LLM。
4. **结果分层(关键步骤)**:后端对 LLM 返回的每条问题做归层校验:
   - 判定为引文的 → 强制归入"引文类",清除修改建议,替换为"原文照录,不建议改动";
   - 涉及人名/职务/历史事实且置信度不足的 → 强制归入"存疑待核实",措辞改为"建议人工核实";
   - 不影响正确性的表达建议 → 归入"风格可选",优先级标为"可选";
   - 其余 → "确定性错误"。
5. **对话式展示**:按分层分组、页码排序,以问题卡形式逐条/分组展示,每条带分层标签和"采纳/拒绝"按钮。
6. **用户追问环节**:用户可就任意一条追问("为什么建议这么改""这是不是误判"),系统携带该条目的原文上下文调用 LLM 回答,回答仅影响该条,不重跑全文。
7. **用户标记环节**:逐条标记"已采纳/已拒绝/待处理",拒绝时可填写理由;状态实时写入 SQLite。
8. **导出**:按第 8 章格式导出 Excel;同时向流程记录表写入本轮统计。

### 5.2 工作流二:原稿比对

```
上传原稿Word + 排版稿PDF/Word → 双份解析 → 段落对齐 → 差异检测
        → 差异分类(排版调整 / 实质性内容改动) → 对话式展示
        → 追问 / 状态标记 → 导出Excel差异清单
```

分步说明:

1. **双份解析**:分别解析原稿与排版稿(排版稿若为 PDF 同样需处理双栏)。
2. **段落对齐**:以段落/句子为单位对齐两份文本(排版稿分页、换行与原稿不一致,需先归一化再对齐)。
3. **差异检测与分类**:
   - **排版调整(不算错误)**:换行位置、空格、连字符、分页导致的差异;
   - **实质性内容改动(需确认)**:文字增删改、标点变化、数字/人名变动等。
4. **对话式展示**:仅"实质性改动"默认展开,排版调整折叠可查;支持追问与状态标记。
5. **导出**:Excel 差异清单,并写入流程记录。

## 6. 关键技术难点

| 编号 | 难点 | 问题描述 | 应对思路 |
|---|---|---|---|
| T1 | 双栏 PDF 阅读顺序识别 | 期刊类 PDF 常见双栏排版,直接抽取文本会串栏,导致校对上下文错乱 | 使用支持版面分析的解析库(如 pdfplumber 按坐标分栏 / PyMuPDF 块排序),按"先左栏后右栏"重排;对识别失败的页面允许人工提示切换单栏模式 |
| T2 | 长文档切割分块 | 100+ 页文档超出单次 LLM 上下文;硬切会把一句话/一个引文切断 | 按页/段落边界切块,块间保留重叠区;记录每块的页码偏移,保证问题定位回原文位置准确 |
| T3 | 引文识别与保护 | 引用的原始文献/古籍/他人原话不得按现代语感修改 | 提示词强制规则:判断为引文一律标"引文类,原文照录,不建议改动";后端二次校验,凡带引号/古文特征命中引文的建议强制降级为提示,清除"应改为"内容 |
| T4 | 事实性内容置信度控制 | AI 可能把正确的人名、职务、历史事实改错 | 提示词要求此类建议必须输出置信度;后端规则:非"充分把握"一律归"存疑待核实",措辞统一为"建议人工核实",禁止确定性结论 |
| T5 | 对话追问的上下文管理 | 追问必须锚定到具体某条问题,且需携带原文上下文;全文太长不能整体塞入 | 会话状态中维护"当前条目 ID → 原文片段(含前后文窗口)+ 该条 LLM 原始判断";追问时只注入该窗口,控制 token 成本 |
| T6 | 比对差异判定 | 需区分排版性差异与实质性改动,直接 diff 噪音极大 | 先做文本归一化(去多余空白、统一换行/连字符),再做段落对齐 + 句级 diff;归一化后仍存在的差异才判为实质性改动 |

## 7. 流程记录字段表

参考出版行业"三审三校"精神,单人使用简化版。每完成一轮校对/比对写入一条记录。

| 字段 | 类型 | 说明 |
|---|---|---|
| record_id | INTEGER 主键 | 自增 |
| created_at | DATETIME | 本轮校对时间 |
| doc_name | TEXT | 文档名(比对流程记录两个文件名) |
| doc_version | TEXT | 版本号(如 v1、二校稿) |
| task_type | TEXT | 校对类型:标准校对 / 原稿比对 |
| total_issues | INTEGER | 问题总数 |
| count_confirmed | INTEGER | 分层统计:确定性错误数 |
| count_doubtful | INTEGER | 分层统计:存疑待核实数 |
| count_quotation | INTEGER | 分层统计:引文类数 |
| count_optional | INTEGER | 分层统计:风格可选数 |
| high_priority_count | INTEGER | 高优先级问题数 |
| accepted_count | INTEGER | 用户采纳数 |
| rejected_count | INTEGER | 用户拒绝数 |
| result_path | TEXT | 导出 Excel 结果文件路径 |

另需一张问题明细表(issues),存每条问题的内容、分层、优先级、处理状态、拒绝理由、追问记录,通过 record_id 关联;字段与第 8 章导出列一一对应,便于导出时直接查询生成。

## 8. 输出格式规范(Excel)

| 列名 | 说明 |
|---|---|
| 页码/位置 | 问题所在页码及段落/行定位 |
| 原文 | 有问题的原文片段 |
| 问题类型 | 十类检查维度之一(错别字、标点、搭配等) |
| 优先级 | 高 / 中 / 低 / 可选 |
| 分层标注 | 确定性错误 / 存疑待核实 / 引文类 / 风格可选 |
| 修改建议 | 确定性错误给出建议;存疑类写"建议人工核实";引文类写"原文照录,默认不建议改动" |
| 处理状态 | 已采纳 / 已拒绝 / 待处理(已拒绝的附拒绝理由) |

格式规则:

1. 按**页码升序**排列;
2. **高优先级问题整行标红**;
3. **引文类用另一种颜色**(如浅黄)区分,并在修改建议列注明"默认不建议改动";
4. 原稿比对的差异清单沿用同一列结构,"问题类型"填"排版调整/实质性改动","分层标注"填差异类别。

## 11. 附录:校对提示词说明

校对标准沿用既有校对提示词的**十类检查维度**(见随附提示词文件),在此基础上必须补充以下两条规则,并在系统层(结果分层模块)做二次强制校验:

### 补充规则一:引文识别与保护

> 凡判断为引用的原始文献、古籍、他人原话的内容,一律标注"引文类,原文照录,不建议改动",**不得直接给出修改建议**。即使引文用字不符合现代语感或现行规范,也不得按"更通顺"的方式改动。

### 补充规则二:事实性内容置信度分级

> 凡涉及人名、职务、历史事件等具体事实的修改建议,**必须标注置信度**。只有在充分把握时才可标注为"确定性错误";凡置信度不足,一律标注"存疑,建议人工核实",不得给出"应改为"的确定性结论。

系统层校验兜底:即使 LLM 输出未遵守上述规则,结果分层模块也会按 T3/T4 的规则强制改写归层,保证进入用户界面和 Excel 的结果符合分层要求。
