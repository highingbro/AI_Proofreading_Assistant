# 阶段1 开发提示词:项目骨架

> 使用方法:将下方分隔线内的全部内容粘贴给 Claude Code。建议把《项目框架文档》也放入项目根目录,供其参考。

---

我要开发一个单人使用、本地运行的出版校对 AI 助手(Python + Streamlit + SQLite)。完整需求见项目根目录下的《项目框架文档_AI校对助手.md》。开发分10个阶段进行,本次只做**阶段1:项目骨架**,后续阶段的功能不要实现,只留好结构。

## 本阶段任务

### 1. 创建项目目录结构

```
proofreader/
├── app.py                  # Streamlit 入口(本阶段只放最简页面骨架)
├── config.py               # 全局配置
├── requirements.txt
├── README.md               # 简要说明如何启动
├── core/
│   ├── __init__.py
│   ├── parser.py           # 文档解析(阶段2实现,本阶段只留空模块+函数签名)
│   ├── chunker.py          # 长文档分块(阶段3,同上)
│   ├── llm_client.py       # LLM调用封装(阶段4,同上)
│   ├── classifier.py       # 结果分层模块(阶段5,同上)
│   ├── followup.py         # 对话追问处理(阶段7,同上)
│   ├── comparer.py         # 原稿比对(阶段9,同上)
│   └── exporter.py         # Excel导出(阶段8,同上)
├── db/
│   ├── __init__.py
│   ├── database.py         # SQLite 连接与建表(本阶段实现)
│   └── models.py           # 数据访问函数(本阶段实现基础CRUD)
├── data/
│   ├── uploads/            # 上传原文件,按轮次归档
│   ├── exports/            # 导出的Excel
│   └── app.db              # SQLite 数据库文件(首次运行自动创建)
└── tests/
    └── test_stage1.py      # 本阶段验收测试
```

空模块只写模块级 docstring(注明属于哪个阶段)和核心函数签名(带类型标注和 `raise NotImplementedError`),不写实现。

### 2. SQLite 建表(db/database.py)

首次运行自动建表,使用如下 schema:

**表一:records(流程记录表)**

| 字段 | 类型 | 说明 |
|---|---|---|
| record_id | INTEGER PRIMARY KEY AUTOINCREMENT | |
| created_at | TEXT | ISO格式时间 |
| doc_name | TEXT | 文档名(比对流程存两个文件名,用" vs "连接) |
| doc_version | TEXT | 版本号,如 v1、二校稿 |
| task_type | TEXT | '标准校对' / '原稿比对' |
| total_issues | INTEGER | 问题总数 |
| count_confirmed | INTEGER | 确定性错误数 |
| count_doubtful | INTEGER | 存疑待核实数 |
| count_quotation | INTEGER | 引文类数 |
| count_optional | INTEGER | 风格可选数 |
| high_priority_count | INTEGER | 高优先级问题数 |
| accepted_count | INTEGER | 采纳数 |
| rejected_count | INTEGER | 拒绝数 |
| result_path | TEXT | 导出Excel路径,可为空 |

**表二:issues(问题明细表)**

| 字段 | 类型 | 说明 |
|---|---|---|
| issue_id | INTEGER PRIMARY KEY AUTOINCREMENT | |
| record_id | INTEGER | 外键 → records.record_id |
| page_location | TEXT | 页码/位置 |
| original_text | TEXT | 原文片段 |
| issue_type | TEXT | 问题类型(十类维度之一,或'排版调整'/'实质性改动') |
| priority | TEXT | '高'/'中'/'低'/'可选' |
| layer | TEXT | '确定性错误'/'存疑待核实'/'引文类'/'风格可选' |
| suggestion | TEXT | 修改建议 |
| status | TEXT | '待处理'/'已采纳'/'已拒绝',默认'待处理' |
| reject_reason | TEXT | 拒绝理由,可为空 |
| context_snippet | TEXT | 原文上下文窗口(供阶段7追问使用),可为空 |
| followup_history | TEXT | 追问历史,JSON字符串,可为空 |

启用外键约束(`PRAGMA foreign_keys = ON`)。

### 3. 数据访问函数(db/models.py)

实现并测试以下基础函数:

- `create_record(...) -> int`:插入一条流程记录,返回 record_id
- `update_record_stats(record_id, ...)`:更新统计字段与结果路径
- `add_issue(record_id, ...) -> int`:插入一条问题,返回 issue_id
- `update_issue_status(issue_id, status, reject_reason=None)`
- `get_issues(record_id, layer=None) -> list[dict]`:按分层筛选查询
- `get_records() -> list[dict]`:按时间倒序列出历史记录

### 4. 全局配置(config.py)

集中定义:数据目录路径(uploads/exports/db)、四个分层的常量名、优先级常量、LLM API 相关配置占位(base_url、api_key 从环境变量读取、model 名,阶段4才使用)。路径统一用 `pathlib.Path`,启动时自动创建缺失目录。

### 5. Streamlit 入口(app.py)

只做最简骨架:页面标题、侧边栏两个功能入口("标准校对"/"原稿比对",点了显示"该功能将在后续阶段实现")、一个"历史记录"页调用 `get_records()` 展示空表格。不实现任何业务逻辑。

### 6. 验收测试(tests/test_stage1.py)

用 pytest 编写,使用临时数据库文件(不污染 data/app.db),覆盖:

1. 建表成功,两张表存在且字段齐全
2. create_record → add_issue → update_issue_status → get_issues 全链路数据正确
3. get_issues 按 layer 筛选正确
4. 外键约束生效(向不存在的 record_id 插 issue 应失败)

## 完成标准

- `pip install -r requirements.txt` 后 `streamlit run app.py` 可启动无报错
- `pytest tests/test_stage1.py` 全部通过
- 目录结构与上述一致,空模块均有 docstring 和函数签名
