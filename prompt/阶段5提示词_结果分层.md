## 模块定位(为什么这层必须存在)

LLM 自报的 category/confidence **不可直接信任**——引文保护和事实置信度分级如果只靠提示词,LLM 不遵守时错误结论会直接流到用户面前。本模块在系统层做强制归层校验:即使 LLM 输出完全不守规则,进入界面和Excel的结果也必须符合四层规范。这是框架文档"设计铁律"第2、3条的落地,是本项目区别于"直接把LLM输出给用户"的核心。

## 本阶段任务

### 1. 数据结构

```python
@dataclass
class ClassifiedIssue:
    # ---- 继承自 RawIssue ----
    original_text: str
    issue_type: str
    suggestion: str          # 注意:可能被本模块改写(见归层规则)
    reason: str
    block_index: int | None
    page_location: str | None
    chunk_index: int
    located: bool
    # ---- 本模块产出 ----
    layer: str               # config.LAYER_* 四层之一
    priority: str            # '高'/'中'/'低'/'可选'
    layer_notes: list[str]   # 归层依据记录,如"LLM自报quotation"/"低OCR置信度降级"
    # ---- 供后续阶段使用 ----
    llm_category: str        # 保留LLM原始自报,便于追问时溯源
    llm_confidence: str
    original_suggestion: str # 改写前的LLM原始建议,追问溯源用

@dataclass
class ClassifiedResult:
    issues: list[ClassifiedIssue]   # 已去重、已排序(页码升序,同页按block_index)
    stats: dict                     # 与 records 表字段对齐的统计(见第4节)
    warnings: list[str]             # 继承chunk_warnings + 本模块新增
```

### 2. 归层规则(核心,按顺序应用,先命中先生效)

对每条 RawIssue 依次判定:

**规则A:引文强制保护(最高优先)**
命中条件(任一):
- LLM自报 category='quotation'
- issue_type 为"引用与成语准确性"且 suggestion 含改字建议
- original_text 或其所在语境带明显引文特征:成对书名号《》内容、成对引号且长度超过短语级(如≥10字)、文言文特征(可用简单启发式:高频文言虚词"之乎者也矣焉哉"密度)

处理:
- layer = 引文类
- suggestion 强制改写为:"原文照录,不建议改动。"+(若LLM原建议提示了具体疑点,追加"LLM提示的疑点供参考:{原reason}")
- priority = '低'
- layer_notes 记录命中依据

**规则B:事实性置信度降级**
命中条件:LLM自报 category='factual',或 issue_type 为"常识与事实性错误",或 original_text 疑似含人名/职务/机构名/年份且建议为改写型
处理:
- llm_confidence == 'high' → layer = 确定性错误(保留建议,但 layer_notes 记"事实类high置信,建议人工复核仍然适用")
- 其他(medium/low/缺失)→ layer = 存疑待核实,suggestion 改写为"存疑,建议人工核实:{原suggestion}"
- priority:高置信 '中',降级后 '中'(事实错误后果重于一般错字)

**规则C:OCR低置信度降级**(实测确认的必要规则:OCR会认错字,如AI→A1、形近字错误,这些会被LLM当成"原文错别字"误报)
命中条件:该 issue 的 block_index 对应 ParsedBlock 的 ocr_confidence 非空且低于阈值(`OCR_CONF_DOWNGRADE_THRESHOLD` 进 config.py,默认0.90),且 issue_type 属于"错别字与拼写"或"标点符号问题"
处理:
- 原 layer 若为确定性错误 → 降级为存疑待核实
- suggestion 前追加"该处文字来自OCR识别且置信度较低,可能为识别误差而非原文错误。"
- layer_notes 记录"低OCR置信度降级(conf={值})"

**规则D:未定位条目降级**
命中条件:located == False
处理:layer 最高只能到存疑待核实(若前面规则已判引文类则维持),layer_notes 记"原文未能定位回原稿"

**规则E:风格可选**
命中条件:LLM自报 category='style',或 suggestion/reason 中含"更通顺""更简洁""建议润色"类措辞且不涉及对错
处理:layer = 风格可选,priority = '可选'

**规则F:默认归层**
以上都未命中(普通 normal 问题):
- llm_confidence == 'high' → 确定性错误
- 其他 → 存疑待核实,suggestion 前不加改写(普通语言问题的低置信不需要"人工核实"话术,保留原建议即可)

**优先级默认表**(规则A/B/E已特判的除外):
- issue_type 属于"政治敏感性表述"/"民族与地名规范" → priority='高',**无论落在哪一层**(对应规则文件"优先标注、单独提醒"的要求;若这两类被降级到存疑待核实,priority 仍为高)
- 其余确定性错误 → '中';存疑待核实 → '中';风格可选 → '可选'

### 3. 跨块去重

阶段4已过滤"仅重叠区命中"的条目,但相邻块正文重叠、或同一 block 被超长切分共享 block_index 时,同一处问题可能被报两次:
- 去重键:(block_index, original_text 归一化后) 相同 → 视为重复
- 保留规则:保留层级更"保守"的一条(存疑>确定性;引文类优先保留),其余丢弃并在 warnings 计数
- located=False 的条目不参与去重(没有可靠的 block_index)

### 4. 统计输出(stats,与 records 表字段对齐)

total_issues、count_confirmed、count_doubtful、count_quotation、count_optional、high_priority_count。字段名与 db/database.py 的 records 表列名一致,供阶段6/8直接写库。

### 7. 测试(tests/test_stage5.py)——全部不耗额度

手工构造 RawIssue 与最小 ParsedDocument,逐条规则精确断言:

**规则A**:LLM自报quotation → 引文类+建议被改写;LLM没自报但original_text含书名号引文 → 仍被拦截为引文类(**这是兜底能力的核心断言**);文言特征命中
**规则B**:factual+low → 存疑+话术改写;factual+high → 确定性但notes有记录
**规则C**:低ocr_confidence的错别字 → 降级+提示语;高ocr_confidence不降级;native文本(ocr_confidence=None)不触发
**规则D**:located=False → 最高存疑
**规则E**:style → 风格可选+priority可选
**规则F**:normal+high → 确定性;normal+medium → 存疑
**优先级**:政治敏感类即使降级也保持priority='高'
**去重**:同block同文本两条 → 保留更保守层;不同block同文本 → 都保留
**规则顺序**:构造同时命中A和B的条目(引文里含人名改动建议)→ 必须落引文类(A先于B)
**stats**:各计数与实际一致,字段名与records表列名一致(用db建表语句反查断言或直接列名对照)

**集成冒烟(@pytest.mark.integration,可选)**:真实样本走全链路,断言不抛异常、每条issue的layer合法、stats自洽(四层计数之和==total)。
